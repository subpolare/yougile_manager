# YouGile Telegram Digest Bot

Бот связывает Telegram-группу с одним проектом YouGile и отправляет свежую сводку
задач по будням в 12:00 по Москве. В личных чатах доступна добровольная подписка на
задачи сотрудника по всем подходящим проектам. Привязки создаются через Telegram и сохраняются в
MySQL. Бот работает одним экземпляром через long polling.

## Конфигурация

Обязательные значения в `.env`:

```dotenv
YOUGILE_COMPANY_ID=your-company-uuid
YOUGILE_API_KEY=your-api-key
TELEGRAM_BOT_TOKEN=your-telegram-token
```

`YOUGILE_COMPANY_ID` сохраняется в конфигурации, хотя рабочие API-запросы авторизуются
уже привязанным к компании ключом.

Сотрудники задаются парами с любым общим префиксом:

```dotenv
IVAN_YG=yougile-user-uuid
IVAN_TG=@telegram_username
```

`*_YG` — UUID пользователя YouGile, `*_TG` — Telegram username. Значение
`*_YG=unknown` означает, что YouGile-сопоставление пока неизвестно. Пустой или невалидный
`*_TG` игнорируется; в сводке тогда используется настоящее имя из списка пользователей
YouGile. Перечень сотрудников в коде не зашит.

`TELEGRAM_CHAT_EDITORS`, `TELEGRAM_CHAT_EDITING` и `TELEGRAM_CHAT_MANAGERS` зарезервированы
на будущее и сейчас не используются для маршрутизации.

## Запуск в Docker

Docker Compose поднимает MySQL 8.4 с постоянным томом `mysql_data`, ждёт успешного
healthcheck и только затем запускает бота. Устанавливать MySQL на компьютер не нужно.
Значения `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD` и `MYSQL_ROOT_PASSWORD` можно
переопределить в `.env`; иначе используются безопасные локальные значения по умолчанию.

```bash
docker compose up -d --build
docker compose logs -f bot
```

Остановка:

```bash
docker compose down
```

Данные MySQL при обычном `down` сохраняются в именованном томе.

Локальный запуск тестов (MySQL и реальные ключи не требуются):

```bash
uv sync --all-groups
uv run pytest -q
```

Тесты используют SQLite только как изолированный async test double для репозитория;
рабочее приложение использует MySQL через `asyncmy`.

## Команды

- `/init 7` — найти единственный допустимый проект с заголовком, начинающимся на `#7`.
- `/init <точное полное название проекта>` — точное сопоставление без fuzzy-поиска.
- `/status` — показать текущую привязку чата.
- `/task` — вручную отправить групповую сводку; в личке — задачи текущего сотрудника.
- `/start` — в личке включить персональную рассылку по будням, без немедленного дайджеста.
- `/stop` — в личке отключить автоматические сообщения, сохранив подписку и доступ к `/task`.

`/init` доступна только администратору или владельцу Telegram-чата. Остальные команды
доступны участникам группы. Один чат связывается ровно с одним проектом, и один проект —
ровно с одним чатом; перемещения выполняются транзакционно. Источник истины — MySQL.

Допустимы только проекты, название которых начинается с `#<число>`. Проекты с префиксом
`#5 Голова` всегда исключены.

## Состав сводки

Учитываются только незавершённые, неудалённые и неархивные задачи с дедлайном из активных
досок и колонок выбранного проекта. Согласно актуальной
[REST API v2 документации YouGile](https://yougile.com/api/), клиент обходит пагинацию
`content`/`paging` (`limit`, `offset`, `next`), использует `/task-list` вместо устаревшего
списка `/tasks` и связывает иерархию project → board → column → task по ID.
В каждой строке сводки перед названием задачи указывается её колонка. Порядок досок и
колонок сохраняется из последовательности `content`, возвращённой API; внутри колонки
задачи идут по точному времени дедлайна, затем по названию.
Подзадачи из массива ID `subtasks` разрешаются по полной пагинированной выдаче
`/task-list` и показываются отдельными пунктами. Для них используются собственные
дедлайн, статус и исполнители; от родителя наследуется только контекст колонки, поскольку
YouGile не возвращает `columnId` у вложенных задач. В строке подзадачи указывается её
непосредственный родитель: `(подзадача внутри «Название родителя»)`.

Дедлайн — поле `deadline.deadline` (конечная дата диапазона). Timestamp переводится в
`Europe/Moscow`, затем задачи попадают ровно в одну группу:

1. сегодня;
2. после сегодня, но строго до ближайшего понедельника (завтра–воскресенье);
3. просрочено — строго до сегодня.

Автоматическая отправка групповых и личных сводок выполняется **понедельник–пятница
в 12:00 Europe/Moscow**. По выходным работает ручной `/task`. При запуске после
пропущенного времени бот не отправляет рассылку задним числом. Успешная отправка
фиксируется в `daily_dispatches`, поэтому перезапуск планировщика не создаёт повторную
автоматическую сводку за тот же московский день. Ручной `/task` эту таблицу не меняет.

## Личные дайджесты

При первом `/start` сотрудник определяется по парам `*_TG`/`*_YG`: `@` необязателен,
регистр username не учитывается, UUID должен быть валидным. `/task` и `/stop` до первого
`/start` не создают подписку. После регистрации источник истины — числовой Telegram ID
и сохранённый YouGile ID, поэтому смена username или удаление пары из `.env` не ломает
доступ. Один YouGile ID нельзя привязать ко второму Telegram ID через совпавший username.
Повторный `/start`, включая вызов после `/stop`, включает существующую подписку.

Личная сводка охватывает все текущие проекты workspace, независимо от `/init`.
Для названий с `#` используется часть до первого `/`; проекты со словами «Голова»,
«Шифры», «Растения», «Рак» в этой части исключаются (целое слово, без учёта регистра).
Остальные проекты показываются с полным названием без окружающих пробелов.
Эти правила не меняют ограничения групповой привязки.

Перед задачей выводится название проекта, исполнители не показываются. У подзадачи
сохраняется непосредственный родитель. Собственные исполнитель, состояние и дедлайн
обязательны; поля родителя не подставляются. В каждой секции сортировка идёт по точному
дедлайну от раннего к позднему, включая просрочку. Будущие даты — `DD.MM`, просроченные —
`DD.MM.YYYY`. Даже пустая личная сводка содержит приветствие и подсказку `/stop`/`/task`.

При старте приложения `create_all` добавляет две таблицы без изменения старых данных:

- `personal_digest_subscriptions`: Telegram ID (PK), уникальный YouGile ID, текущий
  username, `enabled`, даты создания и изменения. `/stop` не удаляет строку.
- `daily_digest_greetings`: московская дата (PK), выбранное приветствие, дата создания.
  Конкурентные первые запросы используют одну победившую запись. Все ручные и
  автоматические, групповые и личные сводки получают приветствие через один провайдер.

На автоматический запуск выполняется один полный пагинированный снимок
`/projects`, `/boards`, `/columns`, `/task-list`, `/users`; личные задачи индексируются по
собственным исполнителям один раз. Ошибка API не превращается в пустой дайджест.
Ошибка доставки одному подписчику не мешает остальным и не отправляется в группы.
Запись в общем `daily_dispatches` создаётся только после успешной отправки всех частей,
под блокировкой строки адресата. Как и раньше, при частичном сетевом сбое повторная
попытка может повторить уже доставленные части: Telegram не поддерживает транзакцию
на несколько сообщений. Бот рассчитан на один экземпляр long polling.
