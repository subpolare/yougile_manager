# YouGile Telegram Digest Bot

MVP-бот связывает Telegram-группу с одним проектом YouGile и отправляет свежую сводку
задач каждый день в 12:00 по Москве. Привязки создаются через Telegram и сохраняются в
MySQL. Бот работает одним экземпляром через long polling.

## Конфигурация

Обязательные значения в `.env`:

```dotenv
YOUGILE_COMPANY_ID=your-company-uuid
YOUGILE_API_KEY=your-api-key
TELEGRAM_BOT_TOKEN=your-telegram-token
```

`YOUGILE_COMPANY_ID` сохраняется в конфигурации, хотя рабочие API-запросы авторизуются
уже привязанным к компании ключом.

Сотрудники задаются парами с любым общим префиксом:

```dotenv
IVAN_YG=yougile-user-uuid
IVAN_TG=@telegram_username
```

`*_YG` — UUID пользователя YouGile, `*_TG` — Telegram username. Значение
`*_YG=unknown` означает, что YouGile-сопоставление пока неизвестно. Пустой или невалидный
`*_TG` игнорируется; в сводке тогда используется настоящее имя из списка пользователей
YouGile. Перечень сотрудников в коде не зашит.

`TELEGRAM_CHAT_EDITORS`, `TELEGRAM_CHAT_EDITING` и `TELEGRAM_CHAT_MANAGERS` зарезервированы
на будущее и сейчас не используются для маршрутизации.

## Запуск в Docker

Docker Compose поднимает MySQL 8.4 с постоянным томом `mysql_data`, ждёт успешного
healthcheck и только затем запускает бота. Устанавливать MySQL на компьютер не нужно.
Значения `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD` и `MYSQL_ROOT_PASSWORD` можно
переопределить в `.env`; иначе используются безопасные локальные значения по умолчанию.

```bash
docker compose up -d --build
docker compose logs -f bot
```

Остановка:

```bash
docker compose down
```

Данные MySQL при обычном `down` сохраняются в именованном томе.

Локальный запуск тестов (MySQL и реальные ключи не требуются):

```bash
uv sync --all-groups
uv run pytest -q
```

Тесты используют SQLite только как изолированный async test double для репозитория;
рабочее приложение использует MySQL через `asyncmy`.

## Команды

- `/init 7` — найти единственный допустимый проект с заголовком, начинающимся на `#7`.
- `/init <точное полное название проекта>` — точное сопоставление без fuzzy-поиска.
- `/status` — показать текущую привязку чата.
- `/task` — вручную отправить ту же сводку, что и ежедневная рассылка.

`/init` доступна только администратору или владельцу Telegram-чата. Остальные команды
доступны участникам группы. Один чат связывается ровно с одним проектом, и один проект —
ровно с одним чатом; перемещения выполняются транзакционно. Источник истины — MySQL.

Допустимы только проекты, название которых начинается с `#<число>`. Проекты с префиксом
`#5 Голова` всегда исключены.

## Состав сводки

Учитываются только незавершённые, неудалённые и неархивные задачи с дедлайном из активных
досок и колонок выбранного проекта. Согласно актуальной
[REST API v2 документации YouGile](https://yougile.com/api/), клиент обходит пагинацию
`content`/`paging` (`limit`, `offset`, `next`), использует `/task-list` вместо устаревшего
списка `/tasks` и связывает иерархию project → board → column → task по ID.
В каждой строке сводки перед названием задачи указывается её колонка. Порядок досок и
колонок сохраняется из последовательности `content`, возвращённой API; внутри колонки
задачи идут по точному времени дедлайна, затем по названию.
Подзадачи из массива ID `subtasks` разрешаются по полной пагинированной выдаче
`/task-list` и показываются отдельными пунктами. Для них используются собственные
дедлайн, статус и исполнители; от родителя наследуется только контекст колонки, поскольку
YouGile не возвращает `columnId` у вложенных задач.

Дедлайн — поле `deadline.deadline` (конечная дата диапазона). Timestamp переводится в
`Europe/Moscow`, затем задачи попадают ровно в одну группу:

1. сегодня;
2. после сегодня, но строго до ближайшего понедельника (завтра–воскресенье);
3. просрочено — строго до сегодня.

Автоматическая отправка выполняется в **12:00 Europe/Moscow**. Успешная отправка
фиксируется в `daily_dispatches`, поэтому перезапуск планировщика не создаёт повторную
автоматическую сводку за тот же московский день. Ручной `/task` эту таблицу не меняет.
